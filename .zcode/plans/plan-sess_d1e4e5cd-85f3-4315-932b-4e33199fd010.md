# Image questions — implementation plan (v0.3.0)

Setup status per your message: ✅ R2 bucket `you-know-images` created, ✅ "Edit R2" added to the Cloudflare API token used by CI.

## Key decisions

**1. Storage: R2 on Cloudflare, filesystem on self-host — behind one interface.**
- R2 free tier: 10GB, 1M writes + 10M reads/month, **zero egress** — serving player images costs nothing. Native Worker binding (`IMAGES` → bucket `you-know-images`).
- Self-host Node gets a small R2-shaped `IMAGES` shim (get/put/delete) reading files from `YK_DATA_DIR/images/` — same dual-runtime pattern as D1→SQLite.
- Rejected: bytes in D1/SQLite (bloats DB + backups), base64 in quiz JSON (quiz JSON is snapshotted into every session DO and pushed over WS — images are referenced by id, never inlined), Cloudflare Images ($5/mo, no self-host parity).

**2. Resize on the client, before upload.**
- Workers free plan has ~10ms CPU per request — server-side wasm resize is a non-starter; client canvas is instant and free.
- Pipeline: `createImageBitmap(file)` → scale so the long edge ≤ **1600px** → `canvas.toBlob('image/webp', 0.85)` → **fallback to JPEG q0.85** when WebP encoding is unsupported (older Safari). Typical result 50–150KB.
- Server still guards: only `image/webp|jpeg|png` via magic-byte sniff, ≤512KB hard cap (413), per-quiz limits (≤50 images, ≤20MB total — the future Free/Pro lever).

**3. Images are immutable and content-referenced.**
- Question JSON stores only `{ imageId, width, height }` — tiny, safe for DO snapshots and WS pushes; width/height reserve layout space so phones don't jump.
- Binary at R2 key `images/<id>` (nanoid); served at `GET /api/images/:id` with `Cache-Control: public, max-age=31536000, immutable`, edge-cached via the Cache API. Changing = delete + re-upload.
- Display uses the existing `radius-thumb` token (17px).

## Changes

**Migration 0004:** `images` table — `id, quiz_id, mime, bytes, width, height, sha256, created_at` + index on `quiz_id`.

**Worker (src/index.ts):**
- `POST /api/quizzes/:id/images?w=&h=` — auth via `x-edit-token` header (same model as quiz edit); magic-byte sniff, caps enforced, put to R2, insert row → `{ id, width, height, url }`.
- `GET /api/images/:id` — public; Cache API → R2 → cache put; immutable headers.
- `DELETE /api/quizzes/:id/images/:imageId` — editor-initiated removal; refused (409) while a session of the quiz is live.
- Quiz `PUT`: verify every referenced `imageId` belongs to this quiz (400 otherwise); **prune-on-save** — delete image rows/objects no longer referenced by the saved quiz.
- Quiz `DELETE`: extend the existing cascade to image rows + R2 objects.

**Shared (types.ts / validate.ts):** `QuestionBase.image?: { id, width, height }`; `validateQuiz` checks shape only — ownership verified server-side where the DB lives. `PublicQuestion` carries the same ref to clients.

**Editor (edit.tsx):** "Add image" per question → file picker → client resize pipeline → upload → thumbnail preview + remove button, wired into the existing autosave.

**Play + Host:** render the image above the prompt (`<img>` with width/height, lazy decode, 17px radius) on phone, projector, and reveal.

**Self-host (server/shims.ts):** `makeImageStore(dataDir)` — R2-shaped get/put/delete over the filesystem, wired as `env.IMAGES` in the Node entry; migration parity in `openDb`.

**Tests:** unit test for the magic-byte sniffer; e2e additions — upload auth (403 wrong token), oversize (413), bad magic (400); attach → `PublicQuestion` carries the ref (no binary leak); `GET /api/images/:id` 200 + immutable header; quiz-delete cascade 404s the image; full parity run against the Node server.
